# Graphics roadmap and acceptance gates

## Scope, evidence and present status

This is the rendering portion of [Goal](../Goal), not a claim that the game or remaster is complete. Original behavior takes priority over optional visual changes. The final native game must not depend on Wine, Proton, Windows DLLs or a launcher process remaining alive. OpenGL must remain a complete standalone compatibility backend; Vulkan is a separate optional backend consuming the same recovered world state.

Evidence labels throughout the project mean:

- **CONFIRMED:** directly supported by the cited file, measurement or observation; confirmation is limited to that evidence's scope.
- **HIGH CONFIDENCE:** multiple supporting observations, but the decisive validation is still missing.
- **HYPOTHESIS:** a proposed interpretation requiring a discriminating experiment.
- **UNKNOWN:** evidence is unavailable or insufficient.

Implementation status is separate from verification and parity. A compiled executable, enumerated GPU, extracted archive or checkbox does not close a rendering/gameplay gate. Parent build/test/native smoke results are recorded in [PROGRESS.md](PROGRESS.md), scoped to exactly the exercised behavior.

## Shared contracts and sequencing

1. Preserve original geometry, handedness, units, winding, UVs, camera matrices, animation timing, material meaning and visibility before enhancing them. Do not infer those conventions from a plausible-looking preview.
2. Keep platform/input, simulation, assets, audio and rendering separate. Both backends consume the same scene/entity/animation/camera state. GPU resource ownership, uploads, synchronization and frame lifecycle belong to each renderer, not gameplay. Refine the renderer interface when evidence requires it; a speculative universal engine is not a prerequisite.
3. Select a practical OpenGL context/shader baseline from tested requirements, and document it. The Vulkan target is 1.3 where available; query exact features, queues, limits and presentation support instead of assuming that an API version enables every feature.
4. Fixed-timestep simulation is appropriate only if original timing behavior is preserved; variable refresh rate or render interpolation must never change movement, collisions, progression, animation or audio synchronization.
5. Preserve legal user-owned assets read-only. Prefer direct loading; require documented, lossless or validated conversion where unavoidable. Every derivative must retain source checksum, format/version, converter version and validation provenance. No original assets enter release artifacts.
6. Renderer selection must ultimately support `--renderer opengl` and `--renderer vulkan`; ray tracing must support `off`, `reflections`, `shadows`, `gi`, and `all`, with independent feature flags. These are **target semantics**, not evidence of current Vulkan support. A request for an unimplemented backend must produce an actionable error, not pretend another backend was used.
7. Do not start Vulkan ray tracing before original asset parsing and basic OpenGL rendering function. Optional remaster work follows a stable playable port. OpenGL parity and non-RT Vulkan remain mandatory throughout.
