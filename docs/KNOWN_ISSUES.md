# Known issues, uncertainty and release blockers

## Reading this register

This project is recovering a proprietary Windows game into native Linux code. The presence of extraction tools, C++ source, a launcher, a GPU or a package does **not** establish a playable or faithful port.

Evidence confidence uses **CONFIRMED**, **HIGH CONFIDENCE**, **HYPOTHESIS**, **UNKNOWN**. Status uses **implemented; verification pending**, **not implemented**, or **blocked on** a stated dependency. Confidence is scoped: a confirmed archive signature does not confirm its contained gameplay semantics. Main-agent exercised checks belong in [PROGRESS.md](PROGRESS.md); none are inferred from compilation here.

Release-blocking means the issue prevents one or more [Goal](../Goal) acceptance criteria from being claimed. Optional-tool limitations can constrain evidence without making all work impossible. See [GRAPHICS_ROADMAP.md](GRAPHICS_ROADMAP.md) for complete phase gates, [REVERSE_ENGINEERING.md](REVERSE_ENGINEERING.md) for binary findings and [FUNCTION_MAP.md](FUNCTION_MAP.md) for original-address mapping.
