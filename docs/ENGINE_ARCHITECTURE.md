# Engine and distribution architecture

## Scope and evidence policy

The target is a native C++20 Linux reconstruction, not a Wine wrapper. The game and Qt 6 launcher are separate executables. Wine may be used only in an isolated reference-analysis environment, not by the final runtime. The original installer and game files are read-only inputs; releases contain no copyrighted game assets or original decompiler output.

`CONFIRMED` means observed in a source, binary, or recorded execution; `HIGH CONFIDENCE` means multiple corroborating clues without full behavioral validation; `HYPOTHESIS` means an investigation candidate; `UNKNOWN` means not recovered. Implementation is not behavioral verification. [PROGRESS.md](PROGRESS.md) records milestone gates and exercised checks.

## Data flow

```text
legally owned installer (read-only)
    -> native extractor in private staging
    -> size/path/count/hash validation
    -> atomic fresh imported root + asset-manifest.json
    -> original-format readers -> inspection renderer

configured GitHub repository + independently trusted public key
    -> HTTPS release discovery
    -> signed manifest and bounded native archive validation
    -> complete immutable version directory -> optional --install atomic activation -> rollback history

Qt launcher settings + validated asset root + selected native version
    -> explicit native process arguments -> SDL3 game/inspection runtime
```

Imported copyrighted assets and mutable user configuration must remain outside native version directories. A native update must not replace either. Root privileges are neither needed nor appropriate for normal installation. Existing destinations are not destructively repaired; failed imports retry into a new destination.

## Extraction transaction

`CONFIRMED`: the importer uses a private staging directory, tests the Inno archive, extracts using a native ELF tool, and validates extracted regular files against the archive listing. Unsafe paths, symlinks and existing destinations are rejected. It records the installer SHA-256 and size, Inno data version, extractor SHA-256, and each payload path/size/SHA-256 in `asset-manifest.json`.

The destination must not exist, including an empty directory. Linux `renameat2(RENAME_NOREPLACE)` commits a verified tree without replacing a racing destination; there is no unsafe fallback. Failure cleans the active stage, leaves original sources/destinations unchanged, and reports an error. A process killed with SIGKILL can leave an uncommitted `.import-...` sibling; later imports never reuse or silently delete it. An optional report path must be fresh and outside the installer/output root.

SIGTERM/SIGINT cancellation cleans private staging and terminates/reaps the extractor child, returning cancellation exit130; repeated SIGTERM is ignored during cleanup. SIGKILL cannot execute cleanup, so a leftover stage is never treated as a committed installation. GUI activation occurs only after full manifest/hash/tree validation.

## Simulation and rendering target

Recovered gameplay owns application states, scene/entity state, inputs, configuration/save behavior, timing, robot movement/transformation/animation, physics/collision, world triggers/objectives/progression, and camera constraints. The renderer consumes common world state and cannot change simulation outcomes. Use a fixed timestep only after determining whether it preserves original timing-dependent behavior.

OpenGL must eventually render the complete game without Vulkan: original geometry, UVs, coordinate conventions, camera matrices, materials, legacy lighting, blending, filtering, animated transforms and frame synchronization. Vulkan is a separate backend over that same world state, not a gameplay rewrite. Modern PBR, reflection/shadow/GI effects and postprocessing are optional and independently configurable; feature queries and a working raster/OpenGL fallback are mandatory. [GRAPHICS_ROADMAP.md](GRAPHICS_ROADMAP.md) defines these gates.

Platform windows/input/display/presentation are isolated from gameplay; assets are isolated from render-backend GPU resources. This keeps X11/Wayland support and future macOS work practical without adding speculative abstractions now. Audio format decoding, playback scheduling and sound-to-animation synchronization require original reference evidence before being called recovered.

## Validation and release gate

Each recovered subsystem needs original-vs-native evidence: unit/integration tests, reference input/time traces, camera/animation/physics/collision/objective/audio comparisons, golden images, native exit/restart tests, sanitizers, GPU validation, captures and performance measurements. Compilation alone cannot satisfy any gameplay or renderer-parity gate. Rendering must remain playable on non-RT GPUs, with measured frame pacing, input latency, memory use, shader-cache behavior, asynchronous loading where useful, FPS limits and high-refresh/VRR behavior.

A release must build/test game and launcher, compile real shaders if present, bundle only permitted runtime dependencies, generate version/schema/checksum manifests, sign artifacts/manifests, and publish installable packages. AppImage and optional native packages, x86-64/ARM64 where actually tested, and a clean-machine install without developer tooling remain explicit acceptance gates. No official repository URL or signing identity is invented.
